# 路线图

## 原则

- **本地优先**：任何新功能都不引入账号、云同步或联网上传。这是产品差异点，也是商店审核的口径。
- **不加 Electron 式的依赖**：UI 仍然是 egui，二进制体积和内存占用是卖点。
- **先做完整的一条路径，再扩**：宁可「随手记」体验闭环，也不要半成品的标签/分类。

## 版本节奏

| 版本 | 主题 | 状态 |
|---|---|---|
| v0.1.x | 剪贴板历史、全局热键、搜索、固定、主题、i18n、自启、商店上架 | 已发布 |
| **v0.2.0** | **快速记录（笔记）** | 规划中 |
| **v0.2.1** | **列表排序** | 规划中 |
| v0.3 | 标签、导出、大输入窗 | 待定 |

## v0.2.0 — 快速记录

目标：有一个灵感时，不用先复制到别处，直接敲进来存下。

### 数据模型

- `Content` 追加 `Note(String)` 变体，`Kind` 追加 `Note`。
- **只能追加，不能重排**：条目用 postcard 序列化，变体索引按顺序编码，插到中间会让旧库解不出来。
- 笔记不走剪贴板采集管道，因此：
  - **不做 BLAKE3 去重**（同一句话允许存两条）
  - **不做 secretshape 过滤**（用户主动输入的内容就是要保存）
- 默认 `pinned = true`：不占 `Config::limit` 配额，也不会被 `retention_days` 清掉。

### 入口

| 入口 | 行为 |
|---|---|
| 全局热键 `Alt+N` | 弹出输入小窗，可改键（复用现有录键组件） |
| 托盘菜单「新建笔记」 | 同上 |
| 主窗口「+ 新建」 | 同上，窗口已打开时不必再切焦点 |

热键注册失败（被别的程序占用）时要有可见提示，并保留托盘与主窗口两个入口。

### 输入小窗

- 单行输入：`Enter` 保存并关闭，`Shift+Enter` 换行。
- `Esc` 取消，内容不落盘。
- 保存后窗口隐藏，焦点还给唤起前的程序。
- 可选开关：保存后把内容写入剪贴板。

### 编辑与删除

- 选中笔记按 `F2` 或双击 → 行内编辑，保存写回同一条（`seq` 不变，位置不跳动）。
- 删除、固定、复制走现有逻辑。

### 筛选与搜索

- 顶部筛选栏加「笔记」，与「文本 / 图片 / 文件」并列。
- 笔记正文进 `TEXTS` 表，复用现有全文搜索。

### 验收标准

- [ ] `Alt+N` → 输入 → `Enter`，条目出现在列表顶部且标记为笔记
- [ ] 同一条笔记连存两次，得到两条记录
- [ ] 笔记超过 `limit` 时不会被容量清理删掉
- [ ] 笔记可以被搜索命中、固定、取消固定、编辑、删除
- [ ] 旧版本数据库直接打开不报错，旧条目正常显示
- [ ] 保存笔记后剪贴板监听不会把它重复采集一遍

## v0.2.1 — 排序

目标：历史列表除了「最近使用」，还能按别的顺序看；笔记能自己排。

### 排序模式

存进 `Config::sort`（`#[serde(default)]`，老配置缺字段时退回「最近使用」）。

| 模式 | 说明 |
|---|---|
| 最近使用 | 现有行为，默认。固定条目仍置顶 |
| 最近创建 | 按创建时间倒序 |
| 最早创建 | 正序，适合把历史当清单看 |
| 按类型 | 笔记 / 文本 / 图片 / 文件 分组 |
| 手动排序 | 拖拽或 `Ctrl+↑↓` 调整，见下 |

### 手动排序

- 新建 `MANUAL_ORDER: EntryId -> u64` 表，**不改 `EntryRecord` 布局**。
- 这样切换排序模式不会丢手动顺序，也不需要数据迁移。
- 新条目插入到手动顺序的末尾（而不是开头），避免打乱已有排列。
- 交互：拖拽行，或选中后 `Ctrl+↑` / `Ctrl+↓`。

### 验收标准

- [ ] 切换排序模式即时生效，不需要重启
- [ ] 手动排序结果重启后仍在
- [ ] 切到「最近使用」再切回「手动排序」，手动顺序没丢
- [ ] 固定条目在非手动模式下仍然置顶

## v0.3 候选（未排期）

- 笔记标签 / 分类
- 导出 Markdown / 纯文本
- 大输入窗（多行编辑器，适合长笔记）
- 托盘快速访问置顶笔记
- 笔记与剪贴板条目之间互相转换

## 明确不做

- 云同步、账号体系
- 任何形式的使用统计或遥测
- AI 摘要 / 自动分类（会引入网络依赖）

## 技术约束与风险

| 风险 | 应对 |
|---|---|
| postcard 不兼容结构体加字段 | 只追加枚举变体；排序状态放独立表 |
| 笔记写回剪贴板后被监听重复采集 | 复用 replay 路径的自写抑制，需补一条测试 |
| `Alt+N` 与常见软件冲突 | 注册失败要有提示；热键可改 |
| i18n 文案漏翻 | 新增文案 zh / en 各一份，CI 里已有 key 一致性检查 |
| 手动排序与分页冲突 | 手动模式下列表一次加载全部可见条目（笔记量级可接受） |

## 待确认

1. 输入框形态：独立全局热键小窗（建议）还是主窗口内输入条？
2. 排序范围：只做下拉排序（建议 v0.2.1 先做），还是同时做拖拽？
3. 笔记是否默认固定（建议是）？
