# 路线图

## 原则

- **本地优先**：任何新功能都不引入账号、云同步或联网上传。这是产品差异点，也是商店审核的口径。
- **不加 Electron 式的依赖**：UI 仍然是 egui，二进制体积和内存占用是卖点。
- **先做完整的一条路径，再扩**：宁可「随手记」体验闭环，也不要半成品的标签/分类。
- **不新开窗口**：能用现有主窗口的视图切换解决的，就不引入第二套窗口生命周期与焦点归还逻辑。

## 版本节奏

| 版本 | 主题 | 状态 |
|---|---|---|
| v0.1.x | 剪贴板历史、全局热键、搜索、固定、主题、i18n、自启、商店上架 | 已发布 |
| **v0.2.0** | **快速记录（笔记视图）** | 已实现 |
| **v0.2.1** | **列表排序（下拉 + 手动拖拽）** | 已实现 |
| v0.3 | 标签、导出、大输入窗 | 待定 |

## v0.2.0 — 快速记录

目标：有一个灵感时，不用先复制到别处，直接敲进来存下。

### 数据模型

- `Content` 追加 `Note(String)` 变体，`Kind` 追加 `Note`。
- **只能追加，不能重排**：条目用 postcard 序列化，变体索引按顺序编码，插到中间会让旧库解不出来。
- 笔记不走剪贴板采集管道，因此：
  - **不做 BLAKE3 去重**（同一句话允许存两条）
  - **不做 secretshape 过滤**（用户主动输入的内容就是要保存）
- 默认 `pinned = true`：不占 `Config::limit` 配额，也不会被 `retention_days` 清掉。

### 窗口与视图

**不新建独立小窗**，改成主窗口内的视图切换：

- 顶部加一级 tab：**历史** / **笔记**（`View::History` / `View::Notes`，不持久化，默认历史）。
- tab 切换时清空搜索框与来源筛选，避免上一个视图的条件被带过去。
- 笔记 tab 里隐藏「来源」筛选（剪贴板来源对笔记没有意义）。
- 历史 tab 的 `KindFilter` 不出现「笔记」，笔记只在笔记 tab 里出现，两个视图的条目集合互斥。

### 入口

| 入口 | 行为 |
|---|---|
| 全局热键 `Alt+N` | 唤起主窗口并切到「笔记」tab，光标落在输入框 |
| 托盘菜单「新建笔记」 | 同上 |
| 主窗口「+ 新建笔记」 | 已在笔记 tab 时直接聚焦输入框 |

- 第二个热键存 `Config::note_hotkey`（默认 `Alt+N`），设置页复用现有录键组件。
- 唤起路径复用现有机制：UI 已启动时发 `UiRequest::ShowNotes`；未启动时用启动参数 `--notes`。
- 热键注册失败（被别的程序占用）要有可见提示，且保留托盘与主窗口两个入口。

### 记录与编辑

- 输入框在笔记 tab 顶部，单行：`Enter` 保存并清空输入框（不关窗，方便连续记），`Shift+Enter` 换行。
- 保存后条目出现在列表顶部，输入框保持焦点。
- 选中笔记按 `F2` 或双击 → 行内编辑，保存写回同一条（`seq` 不变，位置不跳动）。
- 笔记 tab 不显示固定按钮（笔记本身就是永久保留），只保留复制 / 删除。

### 搜索

- 两个 tab 各自独立搜索，笔记正文进 `TEXTS` 表，复用现有全文搜索。

### 验收标准

- [ ] `Alt+N` 唤起主窗口并落在笔记 tab，光标在输入框
- [ ] `Alt+V` 仍然落在历史 tab，两个热键互不干扰
- [ ] `Enter` 保存后条目出现在顶部、输入框清空且保持焦点
- [ ] 同一条笔记连存两次，得到两条记录
- [ ] 笔记超过 `limit` 时不会被容量清理删掉
- [ ] 笔记可以被搜索命中、编辑、删除
- [ ] 切换 tab 后不残留上一个视图的搜索词与来源筛选
- [ ] 旧版本数据库直接打开不报错，旧条目正常显示
- [ ] 保存笔记后剪贴板监听不会把它重复采集一遍

### 实现位置

| 部分 | 位置 |
|---|---|
| 数据模型 | `types.rs`：`Kind::Note`、`Content::Note`、`Scope` |
| 存储 | `redb_store.rs`：`insert_note` / `update_note`，`NOTE_COUNT` 维护两个视图的总数 |
| 协议 | `wire.rs`：`InsertNote` / `UpdateNote` / `UiRequest::ShowNotes` / `SetNoteHotkey` |
| 热键 | `system.rs`：槽位化的 `rebind_at` / `poll_pressed` |
| 界面 | `app.rs`：`View` 切换、`note_composer`、`start_note_edit` |

调试用：`25zai --note "文本"` 写一条笔记，`25zai --dump --notes` 看笔记列表。

## v0.2.1 — 排序

目标：历史列表除了「最近使用」，还能按别的顺序看；笔记能自己排。

### 排序模式

存进 `Config::sort`（`#[serde(default)]`，老配置缺字段时退回「最近使用」）。历史与笔记两个视图各记一份。

| 模式 | 说明 |
|---|---|
| 最近使用 | 现有行为，默认。固定条目仍置顶 |
| 最近创建 | 按创建时间倒序 |
| 最早创建 | 正序，适合把历史当清单看 |
| 按类型 | 笔记 / 文本 / 图片 / 文件 分组 |
| 手动排序 | 拖拽或 `Ctrl+↑↓` 调整，见下 |

### 手动排序

- 新建 `MANUAL_ORDER: EntryId -> u64` 表，**不改 `EntryRecord` 布局**。
- 一张表同时服务两个视图：两个视图的条目集合互斥，共用一个单调递增计数器即可，不需要按视图分表。
- 切换排序模式不丢手动顺序，也不需要数据迁移。
- 新条目追加到手动顺序末尾（而不是开头），避免打乱已有排列。
- 交互：
  - 拖拽行到目标位置（拖到列表顶部/底部边缘时自动滚动）
  - 选中后 `Ctrl+↑` / `Ctrl+↓` 上下移动一格
  - 只在「手动排序」模式下可拖拽，其它模式下拖拽不响应
- 手动模式下固定条目**不再置顶**，完全按手动顺序显示；固定只影响是否被清理。

### 验收标准

- [x] 切换排序模式即时生效，不需要重启
- [x] 拖拽调整后重启，顺序仍在（`MANUAL_ORDER` 落库）
- [x] `Ctrl+↑` / `Ctrl+↓` 与拖拽结果一致（都走 `apply_manual_order`）
- [x] 切到「最近使用」再切回「手动排序」，手动顺序没丢
- [x] 新条目进手动模式时排在末尾，不打乱已有顺序
- [x] 非手动模式下固定条目仍然置顶，手动模式下不置顶

实现位置：`SortMode` / `Config.sort` 在 `crates/erwuzai-store/src/types.rs`，`page_sorted` 与 `set_manual_order` 在 `redb_store.rs`，下拉与拖拽在 `crates/erwuzai-ui/src/app.rs`（`list_view`）。测试：`crates/erwuzai-store/tests/sorting.rs`。

## v0.3 候选（未排期）

- 笔记标签 / 分类
- 导出 Markdown / 纯文本
- 大输入窗（多行编辑器，适合长笔记）
- 托盘快速访问置顶笔记
- 笔记与剪贴板条目之间互相转换

## 明确不做

- 云同步、账号体系
- 任何形式的使用统计或遥测
- AI 摘要 / 自动分类（会引入网络依赖）
- 独立的热键小窗（v0.2 已定用主窗口 tab 替代）

## 技术约束与风险

| 风险 | 应对 |
|---|---|
| postcard 不兼容结构体加字段 | 只追加枚举变体；排序状态放独立表 |
| 笔记写回剪贴板后被监听重复采集 | 复用 replay 路径的自写抑制，需补一条测试 |
| `Alt+N` 与常见软件冲突 | 注册失败要有提示；热键可改 |
| 现有热键后端只支持一个组合 | `SystemHotkey` 需要持有多个注册并让 `poll_pressed` 返回是哪一个被按下（现在只返回 bool） |
| 切 tab 后旧搜索条件残留 | 切 tab 时显式清空 `query` / `source_filter` |
| i18n 文案漏翻 | 新增文案 zh / en 各一份，CI 里已有 key 一致性检查 |
| 手动排序与分页冲突 | 手动模式下列表一次加载全部可见条目（笔记量级可接受） |
